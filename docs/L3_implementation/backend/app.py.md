# `backend/app.py`

## 目的・役割

`nuts_calc_tex.py` を Web 経由で呼び出す Flask API。エンドポイントは `POST /generate-pdf`、`POST /generate-problems`(issue #138)、`GET /renderer-info`(issue #46)の3つ。JSON/HTTP 境界を本ファイルが担う。`POST /generate-pdf` の「内部プレゼンテーション API(3層モデル、issue #183)」の PDF 生成グルー(26個の `_generate_*_pdf` ビルダー、8個の `_is_*_request` ルーティング述語、`_resolve_page_count` / `_build_presentation_pages`、`command_type` → ビルダーのディスパッチ)は issue #290 で `backend/three_layer_renderer.py`([[three_layer_renderer.py]])へ **バイト等価** で抽出した。issue #291 で `generate_pdf()` は、ハードコードした module-level 定数 `_USE_LEGACY_PDF_PIPELINE`(既定 `False`)による全リクエスト単位の1分岐だけを持つディスパッチャに縮小された。issue #297(#174 段3)でその分岐・定数・legacy subprocess 経路(旧 `backend/renderers.py` の `build_command`/`run`)を削除し、`generate_pdf()` は `three_layer_renderer.render_worksheet_pdf(data, PDF_OUTPUT_DIR)` を無条件で呼ぶようになった。どのビルダーにもマッチしないリクエストは `render_worksheet_pdf` が明示的に `ValueError` を送出して HTTP 500 になる(subprocess へ暗黙にフォールバックしない)。`backend/renderers.py` は `backend/renderer_config.py` にリネームされ、レンダラー名解決と共有 `RendererRequest` 型のみを持つ。問題データのみのプロセス内生成は `backend/problem_generation.py` に委譲する。`POST /generate-problems` は issue #228 で `command_type == '100'`(100マス加算表)にも対応し、他コマンドの `{"problems": [...]}` とは別の単一テーブル用 envelope `{"table": {...}}` を返す(#169 の対象外判断を反転)。

## 動作の概要

3つのエンドポイントの JSON/HTTP 境界だけを担う。`POST /generate-pdf` の「内部プレゼンテーション API(3層モデル)」の PDF 生成グルー(26個の `_generate_*_pdf` ビルダー、8個の `_is_*_request` ルーティング述語、`_resolve_page_count` / `_build_presentation_pages`、`command_type` → ビルダーのディスパッチ)は issue #290 で `backend/three_layer_renderer.py` へ **バイト等価** で抽出済み。各ビルダー・述語の検証／生成フロー・呼び出し先シンボルは [[three_layer_renderer.py]] を参照。

- `POST /generate-pdf`(`generate_pdf()`): `paper_size`/`command_type` を検証し、`three_layer_renderer.render_worksheet_pdf(data, PDF_OUTPUT_DIR)` を無条件で呼んでその `(filepath, filename)` を得る(issue #297 で legacy 分岐を削除)。どのビルダーにもマッチしないリクエストは `render_worksheet_pdf` が明示的に `ValueError` を送出し `except ValueError` 節が HTTP 500 にする(subprocess へフォールバックしない)。成功時は `send_file` で PDF を返し、入力・コンパイル・ファイルの各例外は既存の JSON 500 応答へ変換する(`except ValueError` / `except RuntimeError` / `except FileNotFoundError` / `except Exception`)。`except RuntimeError` 節は `three_layer_renderer` のビルダーが `engine_adapter.compile()` の `SystemExit` を捕捉・変換して送出する `RuntimeError` を HTTP 500 にする。
- 既定(3層モデル)経路が扱う `command_type` / variant: `com`(#199)、`ope` の plain/tree/flat multi-term(#205〜#207)、`ope --missing-value`(#223)/`--vertical`(#227)/`--intermediate`(#226)、`99`(#208)、`squ`(#209)、`pi`(#210)、`lcm`(#211)、`gcd`(#212)、`aBc`(#213)、`evenodd`(#214)、`multiples`(#215)、`divisors`(#216)、`frac`(#217)、基本2項 `mixed`(#218)/multi-term・mixed-operator `mixed`(#284)/`reducible_mode` variants(#285)、`divfrac`(#219)、`simplify`(#220)、`frac2dec`(#221)、`dec2frac`(#222)、`commondenom`(#225)、`compare`(#224)、`100`(#229) の 20 command_type 全て。どのビルダーにもマッチしないリクエスト(`mixed` の `reducible_mode` + 多項/`mixed_operators` という `nuts_calc_tex.py` `_init()` も拒否する無効な組合せ、または未知の `command_type`)は `render_worksheet_pdf` が `ValueError` → HTTP 500。
- `POST /generate-problems`(issue #138): 必須パラメータ(`paper_size`/`command_type`/`num`、`num` は正の整数)を本ファイルで検証する。`renderer_config.get_renderer_name()` でレンダラーを解決したうえで、`command_type == '100'`(issue #228)の場合だけ `problem_generation.generate_hundred_square_table(data)` を呼び、その戻り値(`{'table': {...}}`)をそのまま `jsonify` して返す。それ以外は `problem_generation.generate_problems(data, renderer_name)` を呼び、成功時は `{'problems': [...]}` を返す(PDFファイルは生成しない)。`100` は単一の10×10加算表で `num` 個の同型 item のリストにならないため、`problems` list とは別の top-level `table` キーを使う(`num` は全 command 共通の入力検証のため必須のままだが `100` では意味を持たず無視される)。`command_type='ope'` 以外や `ope` の一部亜種フラグ、レンジが狭すぎる `100` など未対応・不正の入力は `problem_generation` 側が送出する `ValueError` を捕捉し `{'error': ...}` を HTTP 500 で返す(`/generate-pdf` と同じ「必須パラメータ欠如は400、ロジック層のエラーは500」という区分けを踏襲)。
- `GET /renderer-info`(issue #46): `renderer_config.get_renderer_name()` の結果をそのまま `{'renderer': 'latex'}` として返す(issue #186 以降、`latex` がデフォルトかつ唯一到達可能なレンダラーのため、通常は常に `'latex'`)。フロントエンドがリクエスト前にどちらのレンダラーが有効かを判定し、`latex` の場合のみ筆算 UI を出す目的で追加された(`frontend/web/src/catalog.js`・`preset.js`・`pcMakeFlow.js` が呼ぶ)。env 変数が不正な場合は `renderer_config.get_renderer_name()` が送出する `ValueError` を捕捉し、`{'error': ...}` を HTTP 500 で返す。

## 統合ポイント

- `frontend/web/src/drillPresets.js` の `g5-gcd` は `command_type: 'gcd'` と `a_min`/`a_max`/`b_min`/`b_max` を送るため、issue #212 の内部 API 経路へ実際に到達する。
- `frontend/web/src/drillPresets.js` の「小学5年生」→「数の性質・九九」にある `g5-evenodd`(表示名「偶数・奇数」、`a_min: 1`/`a_max: 100`)と `g5-multiples`(表示名「倍数」、`a_min: 2`/`a_max: 12`)は、issue #214/#215 の内部 API 経路へ実際に到達する。
- 呼び出し元: `frontend/web/src/catalog.js`・`preset.js`・`pcMakeFlow.js`(`GET /renderer-info`)、`frontend/web/src/presetDetail.js`(`POST /generate-problems`、issue #139。`command_type: 'ope'` かつ未対応フラグなしのプリセットのみ、マウント時・設定変更時にデバウンスして呼び出す)。`frontend/web` には `com`/`pi` を使うプリセットも自由入力フォームも存在せず(`command_type_com`/`command_type_pi` という翻訳文字列だけが `frontend/web/src/strings.ja.json` に孤立して残っている)、`frontend/web` からは `command_type: 'com'`/`'pi'` いずれの `POST /generate-pdf` にも到達不可(issue #210 実装時に `frontend/web/src/drillPresets.js`/`drillCatalog.js` を確認して判明)。かつては `frontend/spa/src/CustomGenerator.jsx` が `command_type: 'com'` を選択できる唯一のフロントエンドだったが、`frontend/spa` 自体が issue #233 で削除されたため、現状 `command_type: 'com'`/`'pi'` の `POST /generate-pdf` へ到達できる UI 経路は存在しない(直接 API を叩けば依然到達可能)。`command_type: '99'` は `frontend/web` から到達可能: `drillPresets.js` の `g2-kuku` プリセットが `dan`(段、`'1'`〜`'9'`)選択時に `command_type: '99'` の `POST /generate-pdf` を送信し、「出題順序」設定に応じて `descend`/`shuffle` も付与する(`dan === 'mixed'` の場合は `command_type: 'ope'` にフォールバックする別経路)。`command_type: 'squ'`(`drillPresets.js` の `ungraded-squ`、`command_type`/`a_value` のみ)、`command_type: 'lcm'`(`g5-lcm`、`a_min`/`a_max`/`b_min`/`b_max`)も `frontend/web` から到達可能。
- 呼び出し先(本ファイルから直接):
  - `backend/three_layer_renderer.py` の `render_worksheet_pdf`(`POST /generate-pdf` の既定経路)。`three_layer_renderer.render_worksheet_pdf(data, PDF_OUTPUT_DIR)` を無条件で呼び、その `(filepath, filename)` を `send_file` する(マッチなしは `ValueError`)。各 `command_type` / variant がどの `nuts_calc_tex` / `problem_generation` シンボル(`generate_*_problems` / `build_*_slot_content_tex` / `resolve_digit_count_range` / `validate_*` / `resolve_hundred_square_axes` / `resolve_term_range` / 各既定値定数など)を呼ぶかは [[three_layer_renderer.py]] の「統合ポイント」に集約されている。
  - `backend/renderer_config.py`: `get_renderer_name` — `POST /generate-problems` / `GET /renderer-info` のレンダラー名解決(issue #297 で `renderers.py` からリネーム、`build_command`/`run` の subprocess 経路は同 issue で削除)。
  - `backend/problem_generation.py`: `generate_problems` / `generate_hundred_square_table`(`POST /generate-problems`)。
- issue #228 の `POST /generate-problems` `command_type == '100'` 経路は PDF/内部プレゼンテーション API を経由せず、`problem_generation.generate_hundred_square_table(data)`(内部で `nuts_calc_tex.generate_hundred_square` を呼ぶ)の戻り値をそのまま `jsonify` する。

## 注意事項・既知の制限

- issue #297 以前は `_USE_LEGACY_PDF_PIPELINE = True` の subprocess 経路で `nuts_calc_tex.py` のバリデーション失敗メッセージ(`print()` = stdout)を `except subprocess.CalledProcessError` ハンドラが `e.stdout` 優先で拾っていた(issue #37 で `exit()` → `exit(1)` に修正されて初めて `CalledProcessError` が発生するようになった経緯を含む)。issue #297 でこの経路・ハンドラ・`import subprocess` は削除された。3層モデル経路のバリデーション失敗は `render_worksheet_pdf` が送出する `ValueError`(→ `except ValueError` → HTTP 500)。
- backend の URL がフロントエンド側にハードコードされている(`frontend/web/src/catalog.js`・`preset.js`・`pcMakeFlow.js`・`presetDetail.js` それぞれの `API_BASE = 'http://127.0.0.1:5000'` の既知の制約)。
- レンダラー選択は env 変数のみで、リクエストごとの指定はできない(issue #36 のスコープ)。`GET /renderer-info` はこの env 変数由来のレンダラー名をフロントエンドに公開する読み取り専用エンドポイントであり、フロントエンドからレンダラーを切り替える手段ではない。
- `_USE_LEGACY_PDF_PIPELINE`(issue #291)とそれが切り替えていた legacy CLI/subprocess 経路(旧 `renderers.build_command`/`run`)、`backend/tests/test_web_backend_renderers.py` の `build_command` テスト群は issue #297(#174 段3、2026-09-01 の `/mtg` で go 判断)で一括削除された。`renderers.py` は `renderer_config.py` にリネームされた。`reverse` / `merge` / `csv` / `debug` の4フィールドは `RendererRequest`(現 `renderer_config.py`)に予約フィールドとして残るが、3層モデル経路では honor されない(`reverse` のみ `99`/`squ`/`pi` で honor、issue #292)。
- 内部プレゼンテーション API 経路(`three_layer_renderer` の各ビルダー)は `nuts_calc_tex.get_latex_engine_adapter()` を直接呼ぶため、`NUTS_CALC_TEX_ENGINE` 環境変数が不正な場合の失敗経路が subprocess command と異なる。内部 API 経路では素の `ValueError` が `generate_pdf()` のルートで HTTP 500 へ変換される。どの `command_type` が内部 API 経路か、各ビルダーのベーシックケース制約(`page` / `with_name_field` / `with_bottom_answer` / `merge` / `descend`・`shuffle` / `reverse` の配線状況)、および `ope` の variant ごとのルーティング述語(`_is_*_request`)の詳細は [[three_layer_renderer.py]] を参照。CLI の `100`(`build_hundred_square_pages`/`--csv`)は無変更で残存する。
