# `backend/three_layer_renderer.py`

## 目的・役割

`POST /generate-pdf` の「内部プレゼンテーション API(3層モデル、issue #183 の `build_presentation_document_tex` / `PresentationPage`)」経路の PDF 生成グルーを一手に担う Flask 非依存モジュール。issue #290 で `backend/app.py` から約2100行(26個の `_generate_*_pdf` ビルダー、8個の `_is_*_request` ルーティング述語、共通の `_resolve_page_count` / `_build_presentation_pages`、`command_type` → ビルダーのディスパッチ)を **バイト等価** で抜き出したもの(#174 の strangler-fig ステップ)。これにより `app.py` は HTTP ルーティングだけに縮小された。

`flask` を import せず、import 時副作用(ディレクトリ生成など)を持たない。入力はリクエスト `dict`(`renderer_config.RendererRequest`)、出力は `(filepath, filename)` タプル。これは 3層モデルへ移行予定の CLI(`nuts_calc_tex.py`)からの再利用を可能にするための制約である。`POST /generate-pdf` の全リクエストがこのモジュールを通り、`render_worksheet_pdf` はどのビルダーにもマッチしないリクエストに対して `ValueError` を送出する(issue #291 以前は subprocess フォールスルーを合図する `None` を返していた)。legacy subprocess 経路(旧 `backend/renderers.py` の `build_command`/`run`)と `backend/app.py` の `_USE_LEGACY_PDF_PIPELINE` 切替定数は issue #297(#174 段3)で削除された。`backend/renderers.py` は `backend/renderer_config.py` へリネームされ、レンダラー名解決と共有 `RendererRequest` 型のみを持つ。

## 動作の概要と主要な判定ロジック・フロー

### 公開エントリポイント `render_worksheet_pdf(data, output_dir) -> tuple[str, str]`

`app.py` の `generate_pdf()` に存在していたディスパッチラダーと **同じ分岐順** で `command_type` / variant を判定する:

0. `command_type` 完全一致: `review`(issue #140、`app.py` 由来のラダー外・新規。ラダー先頭に置く)
1. `command_type` 完全一致: `com` / `lcm` / `divfrac` / `approx` / `gcd` / `evenodd` / `99` / `aBc` / `pi` / `100`
2. `_is_plain_mixed_pdf_request` → `_is_multi_term_mixed_pdf_request`
3. `_is_plain_ope_pdf_request` → `_is_tree_ope_pdf_request` → `_is_multi_term_ope_pdf_request` → `_is_missing_value_ope_pdf_request` → `_is_vertical_ope_pdf_request` → `_is_intermediate_ope_pdf_request`
4. `command_type` 完全一致: `squ` / `multiples` / `divisors` / `frac` / `simplify` / `frac2dec` / `dec2frac` / `compare` / `commondenom`

いずれかに一致すれば対応する `_generate_*_pdf(data, output_dir)` の戻り値 `(filepath, filename)` を返す。**どれにも一致しなければ `ValueError` を送出する**(issue #291)— `command_type == 'mixed'` なら `_MIXED_REDUCIBLE_MULTI_TERM_ERROR`(`reducible_mode` と `terms`/`terms_min`/`terms_max`/`mixed_operators` の併用は不可。`nuts_calc_tex.py` の `_init()`(nuts_calc_tex.py:843-848)も同じ組合せを拒否する)、それ以外(未知の `command_type`)なら `_UNSUPPORTED_REQUEST_ERROR`。`app.py` の `generate_pdf()` の `except ValueError` 節が HTTP 500 に変換する。マッチした場合の内部 API 経路の振り分けは #290 以前と完全に不変で、変わったのは「マッチなし」の挙動が silent な subprocess フォールスルーから明示エラーになった点のみ。<br>この終端 `raise` に到達しうる `mixed` リクエストは、両 `_is_*_mixed_pdf_request` 述語の条件から必ず `reducible_mode is not None` かつ(`mixed_operators` または `terms`系キーあり)になる — つまり上記の無効な組合せに限られる。

### 共通ヘルパー

- `_resolve_page_count(data)` / `_build_presentation_pages(data, order, generate_page, bottom_answer_builder)`(issue #286): 移行済み各 helper に共通するページ生成を集約する。`page` は既定1かつ1以上とし、各ページを既存 CLI と同じ `start_index = (page_number - 1) * (rows * columns) + 1` で個別生成する。`with_bottom_answer` が真で command 固有 builder が存在する場合は各 `PresentationPage.bottom_answer_tex` を設定し、全 helper が `with_name_field` を document builder へ渡す。`100` はページごとに表を1つ生成し、`compare` と `100` の bottom-answer strip は既存 subprocess 経路にも存在しないため指定を無視する。`merge` は引き続き対象外。
- `_IndexedProblem`(Protocol、`index: int`)/ `_IndexedProblemT`(TypeVar): `_build_presentation_pages` のジェネリック境界。
- `_resolve_number_placement(data) -> nuts_calc_tex.NumberPlacement`(issue #355): request から `inline` グリッドの問題番号位置(`nuts_calc_tex.NumberPlacement`)を選ぶ。**短い単行式ドリル**に `_SHORT_DRILL_NUMBER_PLACEMENT`(= `'inline'`。番号+式をまとめて列中央寄せ)、それ以外は既定 `'gutter'`(issue #301 以来の左ガター固定)を返す。全 `_generate_*_pdf` が `ContentAreaLayout(rows=rows, columns=columns, number_placement=_resolve_number_placement(data))` として渡す(`100` の `numbered=False` レイアウトは番号自体がないため対象外)。「短い単行式ドリル」の判定: `columns <= 2`(`_SHORT_DRILL_MAX_COLUMNS`)かつ、`command_type` が `_SHORT_SINGLE_LINE_COMMAND_TYPES`(`99`/`squ`/`pi`/`com`/`evenodd`/`lcm`/`gcd`)、または `command_type == 'ope'` かつ `_ope_is_short_single_line(data)`、または `command_type == 'review'` かつ `_review_is_short_single_line(data)`(issue #365)。
- `_ope_is_short_single_line(data)`(issue #355): plain 2項 `ope`(`a op b =` が毎行1行に収まる)なら真。除外するのは行を複数行化・幅を大きくばらつかせる構造フラグのみ — `use_parentheses`/`vertical`(筆算)/`intermediate`(段階暗算)/`missing_value`/`mixed_operators`(`_OPE_WIDE_LAYOUT_FLAG_KEYS`)と `terms`/`terms_min`/`terms_max`(`_OPE_MULTI_TERM_KEYS`)。**オペランドの桁数・大きさ・小数・余りあり除算・加減混在は除外しない**(grade 3 の 3桁×2桁も1行に収まるため。ユーザーの実機テストで 3桁乗算が `gutter` のままだったのを受けて桁数制限を撤廃した経緯)。conservative allowlist なので非該当 command と `ope` の全 variant はバイト等価を維持する。
- `_review_is_short_single_line(data)`(issue #365): `review` ワークシートは複数ドリルを1グリッドに混ぜるため、**全 `sources` が個別に短1行判定を通る**ときだけ真(各 source を standalone request と同じ規則で判定 — `command_type` が `_SHORT_SINGLE_LINE_COMMAND_TYPES`、または `ope` かつ `_ope_is_short_single_line(source)`)。`sources` が空/非 list、または wide な source(分数・多項チェーン・筆算)が1つでもあれば偽。これにより grade-1 `g1-review`(plain 2項 `ope` ×5)は中央寄せ `inline`、grade-3 `g3-review`(`frac` source を含む)は従来どおり `gutter` でバイト等価を維持する。`g1-review` の recipe が3項計算を含まないのはこの判定を通すため([[../frontend/web/src/drillPresets.js]] 参照)。

### コンパイル失敗の変換

`engine_adapter.compile()` はコンパイル失敗時に例外を raise せず `nuts_calc_tex.failure()`(`print()` + `exit(1)` = `SystemExit`)を呼ぶ設計で、これは元々 CLI の subprocess 隔離を前提にしている(`LatexEngineAdapter.compile` の docstring 参照)。各 `_generate_*_pdf` helper は `compile()` を `contextlib.redirect_stdout` で囲み、`failure()` の出力を捕捉して `SystemExit` を `RuntimeError(f'PDF generation failed: {captured}')` に変換する。`app.py` の `except RuntimeError` 節がこれを HTTP 500 に変換する。

### ビルダー / 述語ごとの詳細

- **群2「mixed / 単発生成系」8ビルダー（`_generate_com_pdf` / `_generate_kuku_pdf` / `_generate_abc_pdf` / `_generate_squ_pdf` / `_generate_pi_pdf` / `_generate_mixed_pdf` / `_generate_hundred_square_pdf`、および #361 で `_generate_mixed_pdf` に統合された旧 `_generate_multi_term_mixed_pdf`）は問題生成パラメータの解決を持たず、`_build_presentation_pages` のコールバックから `problem_generation.generate(<command_type>, data, rows * columns, start_index)` を1回呼ぶだけ**(issue #361、#357 P2-2。群1「ope 直系」の #360 に続く)。共有層が投げる `ValueError` はビルダーを素通りして `app.py` 経由で HTTP 500 になる。移行後も生成 TeX はシード固定 before/after 比較でバイト等価。`100` だけは例外で `generate()` を呼ばない(下記参照)。
- `_generate_com_pdf`(issue #199、共有層移行は issue #361): `com` 専用のベーシックケースのみ。`a_value` の検証(必須、`nuts_calc_tex.MIN_COMPLEMENT_TARGET` 以上。`com` は `DIGIT_COUNT_SHORTHAND_COMMANDS` 外なので値そのものとして読む、issue #230/#237)は共有層 `generate('com', ...)` が所有する。ビルダーは presentation 半分(`rows`/`columns` 既定 10/2 の検証、`build_presentation_document_tex(content_format=build_com_slot_content_tex, page_shell=DEFAULT_PAGE_SHELL, content_area_layout=ContentAreaLayout(rows, columns), show_answer=False)`、engine compile)のみを持つ。
- `_generate_lcm_pdf`(issue #211)/ `_generate_gcd_pdf`(issue #212)(いずれも共有層移行は issue #363): `lcm`/`gcd` は `DIGIT_COUNT_SHORTHAND_COMMANDS` に含まれる。`a`/`b` レンジ解決(`problem_generation.resolve_digit_count_range`)と `math.lcm` / `math.gcd` の選択は共有層 `generate('lcm'/'gcd', ...)`(内部で `_generate_number_pair_problems`)が所有する。variant フラグを持たないためルーティング述語は不要で `command_type` 完全一致でディスパッチする。ビルダーに残るのは `rows`/`columns` 検証・`content_format=build_lcm_slot_content_tex / build_gcd_slot_content_tex`・engine compile のみ。`math` import は #363 でこのファイルから除去(唯一の利用箇所だった)。
- `_generate_divfrac_pdf`(issue #219、共有層移行は issue #362): `a_digits`/`b_digits` または明示 range の解決(`resolve_digit_count_range`)と 0除算回避の `b_min >= 1` 検証は共有層 `generate('divfrac', ...)` が所有する。ビルダーは presentation 半分(`rows`/`columns` 検証、`build_divfrac_slot_content_tex`、engine compile)のみを持ち、未約分 `a/b` 表示を保つ1ページ blank を出す。
- `_generate_approx_pdf`(issue #346、共有層移行は issue #363): `approx`(概数)。`approx` は `DIGIT_COUNT_SHORTHAND_COMMANDS` 外・variant フラグを持たないため `command_type` 完全一致でディスパッチする。`kind`/`round_method`/`round_place`/`sig_digits`/`quotient_decimal_places`/`dividend_decimal_places`/`operator[0]`/`a_min`/`a_max`/`b_min`/`b_max` の `nuts_calc_tex.resolve_approx_params(...)` によるデフォルト解決・feasibility 判定・不正組合せの `ValueError`(`_init()` を経由しない代わりの共有ロジック)はすべて共有層 `generate('approx', ...)` が所有する。ビルダーに残るのは `rows`/`columns` 検証・`content_format=build_approx_slot_content_tex`・engine compile のみ。不正リクエストは `resolve_approx_params` の `ValueError` がビルダーを素通りして `app.py` 経由で HTTP 500 になる。`≒` マーカーが amssymb 由来のため生成 TeX には `\usepackage{amssymb}` が必ず含まれる。
- `_generate_evenodd_pdf`(issue #214、共有層移行は issue #363): `a_min`/`a_max`(既定 `problem_generation.DEFAULT_A_MIN`/`DEFAULT_A_MAX`)のレンジ解決は共有層 `generate('evenodd', ...)` が所有する。ビルダーに残るのは `rows`/`columns` 検証・`content_format=build_evenodd_slot_content_tex`・engine compile のみ。
- `_generate_kuku_pdf`(issue #208、`reverse` は issue #292、共有層移行は issue #361): `99`(九九)専用。`a_value`(必須検証)・`descend`・`shuffle` は共有層 `generate('99', ...)` が所有する(`descend`/`shuffle` は `frontend/web` の `g2-kuku` プリセットが送る生きた出題順序設定なので共有層でも配線済み)。ビルダーに残るのは `reverse`(`data.get('reverse', False)`、プレゼンテーション層の等式 side-swap `c = a x b`。データ層の `descend`/`shuffle` とは別物)を `functools.partial(nuts_calc_tex.build_kuku_slot_content_tex, reverse=reverse)` で `content_format` に束縛する部分のみ。
- `_generate_abc_pdf`(issue #213、共有層移行は issue #361): `aBc` は入力値なし。`rows`/`columns` の既定・検証と `content_format=build_abc_slot_content_tex` のみを持ち、問題は共有層 `generate('aBc', ...)` から取得する(他の群2ビルダーと単一の入口を共有するため `generate_abc_problems` 直呼びを廃止)。
- `_generate_pi_pdf`(issue #210、`reverse` は issue #292、共有層移行は issue #361): `pi` 専用。`a_value`(起点整数、必須検証。`pi` は `DIGIT_COUNT_SHORTHAND_COMMANDS` 外なので直接読む)・`descend`・`shuffle` は共有層 `generate('pi', ...)` が所有する。ビルダーに残るのは `reverse` を `functools.partial(nuts_calc_tex.build_pi_slot_content_tex, reverse=reverse)` で束縛する部分のみ(等式 side-swap `c = a x 3.14`)。
- `_generate_squ_pdf`(issue #209、`reverse` は issue #292、`descend`/`shuffle` は issue #298、共有層移行は issue #361): `squ` 専用。`a_value` 検証(必須のみ、下限なし。`squ` は `DIGIT_COUNT_SHORTHAND_COMMANDS` 外)・`descend`・`shuffle` は共有層 `generate('squ', ...)` が所有する(issue #298 で `99`/`pi` と対称化。`frontend/web` の `ungraded-squ` プリセットは送らないため既定 `False` で従来挙動は不変)。ビルダーに残るのは `reverse` を `functools.partial(nuts_calc_tex.build_squ_slot_content_tex, reverse=reverse)` で束縛する部分のみ(データ層の `descend`/`shuffle` とは別軸の等式 side-swap `c = a x a`)。
- `_generate_multiples_pdf`(issue #215、共有層移行は issue #363): `a_min`/`a_max` レンジ解決、`a_min >= 1` ガード、`multiples_count >= nuts_calc_tex.MIN_MULTIPLES_COUNT` チェックは共有層 `generate('multiples', ...)` が所有する(指定 `multiples_count` は維持)。ビルダーに残るのは `rows`/`columns` 検証・`content_format=build_multiples_slot_content_tex`・engine compile のみ。
- `_generate_divisors_pdf`(issue #216、共有層移行は issue #363): `a_min`/`a_max` レンジ解決と `a_min >= 1` ガードは共有層 `generate('divisors', ...)` が所有する。ビルダーに残るのは `rows`/`columns` 検証・番号なし `content_format=build_divisors_slot_content_tex`・engine compile のみ。可変長の約数リストと `BLANK_ANSWER_TEX` は既存 block formatter と同一。
- **群3「分数系」6ビルダー(`_generate_frac_pdf` / `_generate_simplify_pdf` / `_generate_commondenom_pdf` / `_generate_divfrac_pdf` / `_generate_frac2dec_pdf` / `_generate_dec2frac_pdf`)は問題生成パラメータの解決を持たず、`_build_presentation_pages` のコールバックから `problem_generation.generate(<command_type>, data, rows * columns, start_index)` を1回呼ぶだけ**(issue #362、#357 P2-3。群1「ope 直系」の #360、群2の #361 に続く)。共有層が投げる `ValueError` はビルダーを素通りして `app.py` 経由で HTTP 500 になる。移行後も生成 TeX はシード固定 before/after 比較でバイト等価。群3コマンドはすべて `command_type` 完全一致でディスパッチ(variant 述語なし)。
- `_generate_frac_pdf`(issue #217、共有層移行は issue #362): 分子・分母桁数、`same_denominator`/`different_denominators`、真分数条件、operator(と allowlist)、帯分数 form(と allowlist)、`reducible_mode` ファミリ(値 allowlist + `mul`/`div` 演算子ルール)はすべて共有層 `generate('frac', ...)` が所有する。ビルダーに残るのは `rows`/`columns` 検証・`content_format=build_fraction_slot_content_tex`・engine compile のみ。既存の `\displaystyle`・厳密分数・帯分数表示は不変。operator allowlist(`{add,sub,mul,div,mix}`)/ 帯分数 form allowlist(`{proper,mixed,mix}`、`'improper' or unknown forms` を拒否)/ `reducible_mode` 値 allowlist(`Unknown reducible_mode for the 'frac' command.`)の3つは #362 以前は `_generate_frac_pdf` だけが持っていたが、#357 `/mtg` の「共有層は厳格側に合わせる」方針に従い共有層へ移動し、`POST /generate-problems` も同じ(逐語同一メッセージの)`ValueError` を返すようになった。
- `_generate_simplify_pdf`(issue #220)/ `_generate_frac2dec_pdf`(issue #221)/ `_generate_commondenom_pdf`(issue #225)(いずれも共有層移行は issue #362): `numerator_digits`/`denominator_digits` の `nuts_calc_tex.MIN_FRACTION_DIGITS`〜`MAX_FRACTION_DIGITS` 制限は共有層 `generate('simplify'/'frac2dec'/'commondenom', ...)` が所有する。ビルダーは `rows`/`columns` 検証 + pattern-4b/4c の番号なし slot formatter 合成のみを持ち、既存の `\Rightarrow` 本文を保った1ページ blank を出す。
- `_generate_dec2frac_pdf`(issue #222、共有層移行は issue #362): `frac2dec` と対になる小数→分数変換。`generate_dec2frac_problems(count, start_index)` は digit 引数を取らない(小数桁数は `nuts_calc_tex.py` 側の固定レンジからランダム)ため共有層 `generate('dec2frac', ...)` は `count` 以外に検証すべきパラメータを持たない。ビルダーは `rows`/`columns` 検証 + pattern-4b の `build_dec2frac_slot_content_tex` のみ。

### review

`_generate_review_pdf`(issue #140、`command_type == 'review'`): 複数の別ドリルの問題を1枚に混在させる「総合問題」ワークシート。ラダー先頭でディスパッチする(`app.py` 由来のラダー外の新規ビルダー)。issue #364(#357 P3)で他の全 `_generate_*_pdf` と同じく共有生成層 `problem_generation.generate()` に載せ替えた。

- `_REVIEW_SOURCE_COMMAND_TYPES` = `frozenset(problem_generation._COMMAND_GENERATORS)`: review ソースになれる `command_type`。共有層が扱う 19 種と一致し、`100`(`{"table"}` envelope 専用・`count`-many に分解不可)と `review`(ネスト不可)は元々このキー集合に含まれない。
- `_resolve_review_sources(data)`: `data['sources']`(非空リスト)の**構造のみ**を検証する。各要素は dict で、`command_type` は `_REVIEW_SOURCE_COMMAND_TYPES` のメンバー(外れると `_REVIEW_UNSUPPORTED_SOURCE_ERROR` の `ValueError`)、`num` は int かつ 1 以上。各ソースの個別パラメータ検証は生成時に `problem_generation.generate()` が担う(#364 以前の `_review_*_problems` が持っていた手動の option 転送・部分バリデーションは撤去)。
- `_resolve_review_source_kind(source) -> str`: 1ソースの `ReviewProblem.kind`(= slot formatter 選択キー)を解決する。`ope` 以外は `command_type` そのもの。`ope` は `vertical` 指定なら `ValueError`(review は inline グリッドで tabular を張れない)、`intermediate` 指定なら `'intermediate_ope'`、それ以外は `problem_generation._determine_ope_variant(source)` の variant を `_OPE_VARIANT_REVIEW_KIND`(`tree`→`tree_ope` / `multi_term`→`multi_term_ope` / `missing_value`→`missing_value_ope`)で写像し、plain(`None`)は `'ope'`。
- `_distribute_review_counts(weights, order)`: `num` を相対ウェイトとして扱い、`order`(= `rows * columns`、既定 10×2=20)を最大剰余法でウェイト比按分する。ウェイト合計が `order` に一致する場合は各ソースがウェイトそのままを受け取る。frontend/web の問題数選択(10/20/30)でグリッド数が変わってもプリント常に満杯になるようにするための設計。#364 でも不変。
- `_generate_review_pdf`: `kinds = [_resolve_review_source_kind(s) for s in sources]` を先に一度解決 → ページごとに、各ソースを按分後の個数だけ `problem_generation.generate(source['command_type'], source, count, 1)` で生成し、返った各 dataclass を `nuts_calc_tex.ReviewProblem(index=0, kind=kind, payload=payload)` で包む(`start_index=1` は #364 以前の per-source generator と同じ。`.index` は下の 1..N 採番で上書きされ、生成 RNG には影響しない)→ 連結 → `shuffle` が真なら `random.Random(data.get('review_seed'))` でシャッフル(seed 指定時は決定的。問題値そのものは module `random` 依存でこのシードの対象外)→ ページ内で `start_index = (page_number-1)*order + 1` から 1..N 採番 → `nuts_calc_tex.build_presentation_document_tex(content_format=nuts_calc_tex.build_review_slot_content_tex, content_area_layout=ContentAreaLayout(rows, columns))` でレンダリング。`page` 複数・`with_name_field` は他ビルダー同様に反映。bottom-answer / merge は非対応。
- slot ディスパッチは `nuts_calc_tex.build_review_slot_content_tex` が `_REVIEW_SLOT_CONTENT_FORMATTERS`(kind → 番号なし `build_*_slot_content_tex` の 24 エントリ registry)で行う(番号ボックスは Layer 2 が付与)。`vertical_ope` と `100` は registry 不在で、`_resolve_review_source_kind` / `_resolve_review_sources` が先に弾くためここには到達しない。
- 合成ロジックを `nuts_calc_tex.py` ではなくここに置いたのは CLI(`nuts_calc_tex.py` の positional `command` choices と `_init()`)を無改変に保つため。どのドリルを何問混ぜるかの「レシピ」は呼び出し側(`frontend/web` の学年別プリセット `g3-review`)が持つ。grade 3 の出力は #364 移行後も不変(module `random` を同一シードで固定した before/after 比較でバイト等価を確認済み)。

## 重要な設計判断とその理由

- **Flask 非依存・dict 駆動(import 副作用なし)**: 3層モデルへ移行予定の CLI(`nuts_calc_tex.py`)からの再利用を可能にするため。`generated_pdfs` ディレクトリ生成は `app.py` に残す。
- **バイト等価な抽出(#290)**: `app.py:25-2145` を無改変で移設した(`class _IndexedProblem` から `_generate_hundred_square_pdf` まで)。挙動変更なし・byte-identical PDF 出力が完了条件。
- **マッチなしを `None` 返しではなく `ValueError` 送出にした理由(#291)**: #290 では戻り型 `tuple[str, str] | None` の `None` を「この `command_type` は内部 API 経路の対象外」の合図とし、`app.py` が `renderers.run(...)` へフォールバックしていた。#291 で `_USE_LEGACY_PDF_PIPELINE`(既定 `False`)が全リクエストをこのモジュールへ固定したため、マッチなしは「一時的に未実装」ではなく「無効なリクエスト」を意味する。そこで戻り型を `tuple[str, str]` に絞り、終端で明示的に `ValueError` を送出する — silent な subprocess フォールスルーを排除し、`except ValueError` 節で HTTP 500 にする。分岐順は `generate_pdf()` の旧ラダーと完全一致のまま。issue #297 で legacy subprocess 経路と `_USE_LEGACY_PDF_PIPELINE` 定数自体が削除され、この経路が唯一の `/generate-pdf` 実装になった。
- **`RendererRequest` は `renderer_config.py`(issue #297 で `renderers.py` からリネーム)に据え置き**、本モジュールは import して型注釈に使う(issue #290 スコープ)。
- **`reverse` を `functools.partial` で束縛する理由(#292)**: `build_presentation_document_tex` の `content_format` 契約は `Callable[[problem, show_answer], str]`(`nuts_calc_tex.py:1773` が `content_format(problem, show_answer)` で呼ぶ)。`reverse` は問題データではなくプレゼンテーション層のオプションのため、slot builder に `reverse: bool = False` を追加し `functools.partial(build_*_slot_content_tex, reverse=reverse)` で束縛する。これで `build_presentation_document_tex` のシグネチャも呼び出し箇所も無改変のまま、`99`/`squ`/`pi` の3 helper だけが `reverse` を通す。`aBc` は矢印変換(`abcd ⇒ 値`)で入れ替える等式がなく、legacy 経路にも `reverse` パラメータが存在しないため対象外。

## 注意事項・既知の制限

- 各 `_generate_*_pdf` はベーシックケース限定である: 常に `page` 数の blank(練習用)ページを返し、`with_name_field` と、command 固有 bottom-answer builder がある場合の `with_bottom_answer` を反映する。`compare`/`100` は subprocess 経路にも bottom-answer strip がないため `with_bottom_answer` を無視する。`merge` と filled answer page は未配線。`99`/`squ`/`pi` は `descend`/`shuffle` も配線済み(`squ` は issue #298 で `99`/`pi` に合わせて対称化)。`99`/`squ`/`pi` は `reverse`(等式 side-swap)を issue #292 で `functools.partial` 経由で配線した(他 command の `reverse` は依然として3層レンダラー非対応)。
- 内部 API 経路は `nuts_calc_tex.get_latex_engine_adapter()` を各 `_generate_*_pdf` から直接呼ぶため、`NUTS_CALC_TEX_ENGINE` 環境変数が不正な場合の失敗経路が subprocess command と異なる(素の `ValueError` が `app.py` のルートで HTTP 500 に変換される)。
- `lcm`/`gcd`/`divfrac`/`approx`/`evenodd`/`99`/`aBc`/`pi`/`squ`/`multiples`/`divisors`/`frac`/`simplify`/`frac2dec`/`dec2frac`/`compare`/`commondenom` は専用述語を介さず `command_type` の単純一致でディスパッチする(`ope` と異なり別コンテンツフォーマットパターンを要求する移行済みバリアントがないため)。`approx` の `kind` 分岐は `nuts_calc_tex` 側(`generate_approx_problems`)が持ち、3層レンダラーは単一の slot formatter を渡すだけ。`compare` は option flag を持つが issue #224 の scope が既定オプション限定で generator も非既定値を許容するため bare exact-match 分岐にしている。
- `ope` は plain / tree / flat multi-term / `--missing-value` / `--vertical` / `--intermediate` の各 variant を個別述語で振り分ける。いずれの述語にも当たらない `ope`(無効な variant 併用など。例: `use_parentheses` + `vertical`)は終端の `_UNSUPPORTED_REQUEST_ERROR` で `ValueError` → HTTP 500 になる(#291 以前は `None` 返しで subprocess 経路へフォールバックし、そこで CLI が拒否していた)。CLI の `100`(`build_hundred_square_pages` / `--csv`)は無変更で残存する。
- `review`(issue #140)は `command_type` 完全一致でディスパッチする、`app.py` 由来のラダー外の新規ビルダー。issue #364(#357 P3)で共有生成層に載せ替えられ、合成対象のソース `command_type` は共有層が扱う 19 種すべて(`_REVIEW_SOURCE_COMMAND_TYPES`)に拡大した — standalone メニュードリルと同じ option 集合が効く。`100`(`{"table"}` envelope)・`ope --vertical`(tabular グリッド必須)・`review` ネストは非対応で `ValueError` → HTTP 500。CLI に `review` サブコマンドは無い(合成は本モジュール専用、`nuts_calc_tex.py` 無改変)。`POST /generate-problems` も `review` 非対応。
